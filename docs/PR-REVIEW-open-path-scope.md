# 下载完整性和路径范围复核

PR #7 合入扫描根限制，PR #8 合入下载和本地文件识别改动，PR #9 补回原审查说明。以下记录对应 v0.5.3 的生产路径与回归用例。

| 场景 | 实现与验收证据 |
| --- | --- |
| 库内打开与删除 | `library::resolve_scan_path` 返回实际校验过的规范路径。四个文件系统测试覆盖根内文件、根外文件、同名前缀兄弟目录和无法解析的根，均随库测试运行。 |
| 临时指定的保存目录 | 队列与完成通知只传任务 ID。后端从任务记录定位最终文件或断点，独立于库扫描根。测试 `reveals_only_the_selected_task_file_in_a_custom_directory` 覆盖暂停、完成和校验失败状态。Windows 桌面复核还检查了资源管理器实际选中的文件，名称含中文、空格和逗号。 |
| 单流和分段恢复（R1/R3） | 探测、已保存的版本和分块响应使用相同的版本判断。弱 ETag 无法用于 If-Range。仅有日期时，需要原响应提供足够的 Date / Last-Modified 时间差。旧断点的强 ETag 仍可用。测试覆盖有效前缀复用、旧分段重下、弱标签、版本变化、分块缺少版本标识后的单流回退。 |
| 长度与摘要（R2） | HTTP 长度在传输判断中区别已知零与未知。使用本地 HTTP 响应验证空文件、无长度且无摘要时保留断点、有摘要时交付完整字节，以及错误偏移的 200 + Content-Range。队列比对预期摘要并记录验证结果。 |
| 删除与取消（R4） | 重置时先删除数据文件，再清理版本信息。Windows 文件共享测试在实际持有句柄时检查错误和断点信息。队列取消清理失败会进入可见的错误状态，释放文件后可重试。 |

## 补审的调用路径

- **分段引擎。** 从 Range 探测跟踪到分块分配、旧单流转换、定期检查点、worker 收尾和最终改名。转换旧前缀和复用已写分块都需要版本证据。回退时先停止网络等待并回收 worker，再清理断点和开始完整请求。
- **队列与持久化。** 核对调度并发槽、active/pausing 的收尾、取消和重试、恢复时的待校验任务，以及终态记录删除。终态判断与记录删除位于同一临界区。现有测试覆盖完成与暂停的竞争、启动恢复、同路径写入冲突和不匹配文件保留。
- **摘要缓存与镜像。** 核对 `DigestCache::lookup/digest`、文件句柄和路径在摘要读取前后的标识、镜像所有者及预期摘要规范化。只有可验证文件身份的记录进入缓存命中路径。相同大小并恢复修改时间的文件改写、旧任务和无记录文件均有测试。
- **前端。** 核对仓库详情的目录选择、本地检查结果与请求范围、任务推送的顺序合并、通知及库/队列定位入口。任务完成后有待校验摘要时，通知等到校验结果。类型检查、前端回归与生产构建覆盖此次修改。
- **来源与发布。** 沿 Hugging Face 和 ModelScope 的列表解析、版本和路径编码、请求上下文进入下载引擎。上游协议差异用本地 HTTP fixtures 验证。Windows CI 检查发布版号、前端、后端与安装包，标签流程核对可执行文件校验值及更新签名。

真实上游大模型传输、安装升级和断电恢复属于不同的运行环境。此记录中的本地结果来自可重复的小文件、进程内模拟服务、Windows 文件系统和桌面 Shell。
